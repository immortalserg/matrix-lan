# Работа с Matrix LAN

1. Прочитай `README.md`. Это источник команд установки. `install.sh` вызывает `install.py`, который создаёт конфигурацию, базы и первый аккаунт на Linux-хосте с Docker.
2. Проверь `docker compose version`, `docker info` и `python3 --version`. Уточни постоянное DNS-имя Matrix, если устанавливаешь на реальный сервер. Для теста используй отдельный каталог `--runtime`, уникальный `--project` и отдельный loopback-порт. Начни с `--core`, затем проверь нужные мосты.
3. В проекте `services/` находятся исходники и Dockerfile, `templates/` содержит параметры без секретов. Проект Compose и локальная конфигурация появляются в выбранном `runtime`. PostgreSQL создаёт базы Synapse, WhatsApp, Telegram и LinkedIn, а мосты с SQLite создают свои файлы сами.
4. После `prepare` запусти `start`, проверь список контейнеров и `GET /_matrix/client/versions` через Caddy. Используй локальный CA, полученный командой `python3 install.py ca`, и проверяй TLS. Для рабочего стенда проверь `/config.json` Element, затем вход и один сценарий в согласованном тестовом чате.
5. `templates/services.json` содержит параметры служб. `compose_spec()` добавляет сборки, монтирования и сеть. WeChat и его Matrix-шлюз делят сетевой namespace. Для собственных мостов ищи код в их подпапках. Кастомные файлы Element лежат в `services/element/overlay/`, а основной Element берётся из базового образа.
6. Диагностируй сбой командами `ps` и `logs` только для нужного проекта. Проверяй по очереди HTTPS, PostgreSQL, Synapse и соответствующий мост. Статус контейнера или Matrix-событие сами по себе не подтверждают, что внешний получатель прочитал сообщение.
7. Сгенерированные токены, пароли и данные аккаунтов должны оставаться в локальной установке. Не переноси в Git `bootstrap.private.json`, развёрнутый Compose, файлы под `runtime/`, браузерные профили, дампы, вложения или переписки. Используй искусственные данные для тестов и не подменяй существующие базы при проверке установки.
